# src/lib notes

- Public /pay links need the invoice's pay_token (?k=); build them only with invoicePayUrl(origin, id, token), so an invoice id alone never reveals details.
- Cleaners can write jobs only to move status forward and stamp actual_start/actual_end at the current time (guard_employee_job_billing allowlist); add any new cleaner-side job write as a checked SECURITY DEFINER RPC, so cleaning details stay manager-only.
- Business texts (sms_messages, sms.functions, sendClientSms) are owner/manager-only at both the database and server level, so cleaners never see client conversations.
- Photo upload shrinking and on-phone previews keep a per-photo pending marker and sends the original when a previous shrink never finished (two crashes disable shrinking on that phone), and the outbox resend starts a few seconds after launch, so a memory crash can't repeat on every app open.
- Job-photo uploads name files with the phone's photo id (photoUploadStem, "-p-"), so a resend reuses the stored copy; the hourly stuck-photos hook emails the owner (Outlook, per-file activity-log claims, at most once) about "-p-" files left unattached past the grace period — never auto-attach or delete them.
- Team schedule-reminder texts (appointment_reminder_employee, channel sms) are sent only by employee-reminder-sms.server from the process-push cron, employees only, with the same stale/published checks and a 30-minute lateness cutoff; reminder-setting saves call resync_employee_appointment_reminders so upcoming cleanings pick up new channels.
- Invite links carry our own code (hashed in staff_invites, exchanged by public redeemInviteLink for a fresh magic link), so link lifetime is ours, not the auth OTP expiry; handle_new_user must tolerate admin-created users being confirmed after INSERT (it also fires on the email_confirmed_at UPDATE).
- Schedule time off lives in employee_time_off (owner/manager write; read by owners/managers and the person only), separate from tenant-readable employee_unavailability, so reasons/notes stay private; approving a time_off_request upserts its whole-day row via syncApprovedTimeOff and declining removes it.
